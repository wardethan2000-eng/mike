# 6. Transcripts and chronologies

**Size: medium.** Two related pieces of litigation work Mike cannot do today.

## Transcripts, cited properly

A deposition is cited by page and line — "42:17-19" — not by page. Mike cites
by page only, so it cannot produce a citation anyone would accept in a brief.

**What you would see:** upload a transcript, ask what a witness said about the
inspection, and get the answer with a proper page-and-line citation.

**How it would work:** transcripts are laid out predictably, with numbered lines
down the page. That structure can be read and kept, so each passage carries its
page and line, and citations are built from it. This also makes transcripts work
properly with search across a matter, which otherwise treats them as flat text.

## Chronologies

**What you would see:** point at a set of documents and get a table of what
happened when, each row citing the document and page it came from — the
skeleton of a case summary, built in minutes rather than an afternoon.

**How it would work:** this is what the review grids already do, aimed at a
different target. Each document is asked for the dated events it contains; the
answers are merged, sorted, and duplicates collapsed. The grid machinery,
citations and export all exist already.

## What to watch

- **A date is not always a date.** "Thirty days after completion" is an event
  too. Record what the document says, and only work out the actual date where it
  can be done reliably.
- **Contradictions are the point.** Where two documents disagree about when
  something happened, show both rather than silently picking one.
- **Line numbers must survive OCR.** A scanned transcript needs its line numbers
  preserved, which is worth testing specifically.

## Done when

A real transcript can be quoted with a correct page-and-line citation, and a
chronology built from a mixed set of documents is right, ordered, and cites its
sources.
